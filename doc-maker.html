プライバシーポリシー

最終更新日: 2026年8月25日 ／ バージョン: 1.9.0

本プライバシーポリシーは、Chrome拡張機能「デジカル書類作成くん」（以下「本拡張機能」）における ユーザーデータの取り扱いについて説明します。

本拡張機能は、医師等の医療従事者がデジカル（電子カルテ）を用いた診療業務の中で使用することを 想定した業務効率化ツールです。一般の患者様がご利用になることは想定していません。

1. 単一の目的（Single Purpose）

本拡張機能の唯一の目的:
デジカル（digikar.jp）のカルテ情報をもとに、医師が患者に提出する書類 （病児保育医師連絡票・紹介状（診療情報提供書）・インフルエンザ・COVID-19 証明書（大人）・ 登園・登校届・登園許可証（その他の感染症）・診断書（自宅療養）・診断書（一般））のWordファイル（.docx）を、入力代行および自動命名によって 作成する作業を補助することです。
本拡張機能は、この目的以外の機能（広告表示・ユーザー追跡・SNS連携・分析計測など）を 一切持ちません。

2. 収集する情報の種類

本拡張機能は、ユーザー（医師）が拡張機能を操作した際に、デジカル（digikar.jp）の カルテ画面・公開APIから以下のデータを読み取ります。

分類 具体的内容
個人識別情報 患者氏名・カナ氏名・生年月日・性別・年齢（年齢はAPIレスポンスに含まれますが書類生成には使用しません）
健康に関する情報 病名、現病歴、所見（A/P：評価・計画）、検査結果、受診日、処方の有無（薬剤名そのものは保持せず、 「有／無」のみを判定に使用）、その日の担当医師名
Webサイトのコンテンツ デジカルのカルテ画面・診療記録本文（SOAP形式）のテキスト
認証に関する情報 ユーザーが任意で設定するGoogle Gemini APIキー（ユーザー自身が取得したキーで、端末内にのみ保存）
その他ユーザー入力 院プロファイル（院名・住所・電話番号・FAX番号など、医師が書類の発行元として設定する情報）

本拡張機能は、以下のデータを収集しません: 位置情報、決済・財務情報、 デジカル以外のウェブサイトの閲覧履歴、薬剤名そのもの（処方の有無のみ判定）。

担当医師名の取り扱いについて（v1.8.9 以降）： 書類の「担当医師」欄に入れる医師名は、デジカルの公開APIの返事から取得します （取得元そのものは従来と変わりません）。 v1.8.9 では、返事から医師名を取り出す箇所をプログラム上の1か所にまとめました。 取り出すのは担当医の氏名1項目のみで、 同じ返事に含まれる住所・電話番号・保険・会計の各項目には触れません。 返ってきた値が氏名の形になっていない場合（デジカル側の作りが変わった場合等）は、 その値を書類に使わず、その旨を画面でお知らせします （誤った氏名が書類に印刷されることを防ぐためです）。 公開APIから医師名が得られない場合（レセコン未連携・承認前・会計確定前など）に カルテ画面の表示から控えとして読み取る動作は、従来どおりです。 いずれからも取得できないときは空欄のままとし、 別の氏名で補うことはありません。

3. データの使用目的

読み取ったデータは、以下の処理にのみ使用します。

  • 選択した書類テンプレートの各項目（トークン）へ差し込み、Wordファイル（.docx）を生成すること
  • ダウンロードするファイル名の自動生成（作成日・患者番号・カナ氏名・書類の種類を使用。v1.8.4 より患者番号を含めます）
  • 紹介状・病児保育連絡票の下書き文章を、Gemini APIを用いて要約すること（ユーザーが要約ボタンを 押した場合のみ。詳細は次項）

上記以外の目的（広告・分析・ユーザープロファイリング等）には一切使用しません。

4. Google Gemini APIへのデータ送信について（重要）

本拡張機能は、紹介状・病児保育連絡票・診断書（一般）の要約下書きを作成する機能に限り、Google Gemini API （https://generativelanguage.googleapis.com/）へデータを送信します。

  • 実行タイミング: ユーザーが「AIで要約」等のボタンを押した時のみ実行されます。自動送信は行いません。
  • 使用するAPIキー: ユーザー自身が取得・設定したGemini APIキーを使用します。開発者のキーは使用しません。
  • 送信内容: 現病歴のテキスト・検査結果のテキスト・所見（A/P）のテキスト・受診日（日付のみ）。
  • 送信しない情報（最小化・多層防御設計）: 患者氏名・カナ氏名・生年月日・患者番号・ 担当医師名などの識別情報は、Gemini API呼び出しのメッセージ構造そのものに含める項目（キー）が 用意されていません。仮に呼び出し元から誤って渡された場合でも、拡張機能内部（background.js）で 無視される設計（多層防御）になっており、識別情報がGemini APIへ送信されることはありません。

送信されたデータの取り扱いは、Googleの 「Gemini API追加利用規約」 および「Googleプライバシーポリシー」 に従います。無料枠（Free Tier）のAPIキーで送信されたデータは、Googleのモデル学習に利用される 可能性がある点にご留意のうえ、有料プランのAPIキーのご利用を推奨します。

5. データの保存場所と保持期間

  • 院プロファイル（院名・住所・電話・FAX）・Gemini APIキー・モデル設定・最後に選択した テンプレートID・選択中の院ID: ブラウザのローカルストレージ（chrome.storage.local） にのみ保存され、開発者や外部サーバーへ送信されることはありません（前項のGemini送信を除く）。
  • カルテから読み取った患者情報（氏名・生年月日・住所・年齢・担当医師名・ カルテ本文＝現病歴・検査結果・評価と計画など）は保存しません。 書類作成のためにその場で使用されるのみで、パネルを閉じる・拡張機能を再読み込みする等で 消去されます。
  • 書きかけの書類は、作業を失わないために一時保存します（v1.4.0 以降）。 保存するのはユーザーが自分で入力した文章だけ（診断書の本文・病状・特記事項・ 傷病名・発症日・自宅療養期間終了日・紹介先医療機関など）で、上記のカルテから読み取った 患者情報は一時保存の対象外です。
    置き場所はブラウザのメモリ上（chrome.storage.session）で、 ディスクには書き込まれません。次のいずれかで消去されます。
    　①保存から30分が経過したとき
    　②読み取り元のカルテのタブを閉じたとき
    　③Chrome を終了したとき
    書きかけを戻すのは同じ患者のカルテを開いているときだけ（患者番号で判定）で、 戻した場合は「◯分前の書きかけを戻しました」と画面に表示します。 開発者や外部サーバーへ送信されることはありません。
  • 拡張機能をアンインストールすると、保存されているすべてのデータ（院プロファイル・APIキー等）が削除されます。

6. 生成したWordファイルの取り扱い

作成された書類（.docx）は、拡張機能内でローカルに生成され、ユーザーのPCへ直接ダウンロードされます。 本拡張機能が生成したファイルをどこかへアップロードしたり、外部サーバーに保存したりすることは一切ありません。

v1.8.4 より、ファイル名に患者番号を含めています （例：「2026-08-21　1234567　タナカ　タカシ　登園許可証.docx」）。 同姓同名の取り違えを防ぐためで、この番号はカルテのアドレスに含まれているものをそのまま使います。 番号はお使いのPCのダウンロードフォルダのファイル名として残りますので、 ファイルを外へ渡す場面ではご注意ください。外部への送信は一切行いません。 番号を取得できなかった場合は「番号未取得」と入ります。

7. 第三者へのデータ提供

本拡張機能は、開発者が運営する外部サーバーを持ちません。第4項に記載したGoogle Gemini APIへの 送信を除き、読み取ったデータを第三者へ提供・送信することは一切ありません。解析・トラッキング・ 広告目的のデータ収集も行いません。

8. データの販売・共有

本拡張機能は、ユーザーデータを第三者へ販売・貸与・共有することは一切ありません。

9. アクセス範囲・必要な権限について

本拡張機能はデジカル（https://digikar.jp/*）およびGoogle Gemini API （https://generativelanguage.googleapis.com/*）のドメインでのみ動作します。 その他のウェブサイトへのアクセスは行いません。

権限 用途
sidePanel 書類作成の操作画面をChromeのサイドパネルとして表示するため
storage 院プロファイル・Gemini APIキー・モデル設定・最後に選択したテンプレートIDをローカルに 保存するため（chrome.storage.local）
ホスト権限 https://digikar.jp/* カルテ画面から診療記録・患者基本情報を読み取るため（content script・公開APIの利用）
ホスト権限 https://generativelanguage.googleapis.com/* ユーザーが要約ボタンを押した時にGoogle Gemini APIへ通信するため

これらの権限は本拡張機能の単一の目的を達成するために必要最小限のものです。

デジカルへの問い合わせの待ち時間について（v1.9.0 以降）： カルテの内容を読み取る問い合わせには待ち時間の上限（8秒）を設けています。 相手から返事が返らないまま画面が「読み込み中」の表示で戻らなくなることを避けるためで、 上限を過ぎたときは待つのをやめ、失敗した旨を画面に表示します。 読み取る項目・通信先・保存する内容に変更はありません。

10. Google API ユーザーデータポリシー（Limited Use）への準拠

本拡張機能は、Google Gemini APIを利用するにあたり、Google APIサービスのユーザーデータポリシー （Limited Use要件）を遵守します。

  • 取得したデータは、本拡張機能の単一の目的（書類の下書き作成補助）のためにのみ使用します。
  • 取得したデータを広告目的には一切使用しません。
  • 取得したデータを、開発者を含むいかなる人間が読み取ることもありません （Gemini APIへの送信時を除き、すべてユーザーの端末内で処理されます）。
  • 取得したデータを、本拡張機能のユーザー（医師）に提供する目的以外で第三者へ転送しません。

11. 医療安全に関する補足

本拡張機能は、医師の文書作成業務を補助する目的のツールであり、診断や治療方針の決定を代替する ものではありません（医療機器プログラム（SaMD）には該当しません）。AIによる要約・下書き生成は 文章作成の補助にとどまり、医学的判断は行いません。生成された書類の内容は、必ず医師本人が確認・ 修正したうえで発行してください。

12. ユーザーの権利（削除・開示請求）

本拡張機能は患者情報を保存しないため、患者情報について開示・削除請求の対象となるデータは ありません。院プロファイル・Gemini APIキー等の設定情報は、拡張機能の設定画面からいつでも 変更・削除でき、アンインストールによってすべて削除されます。本ポリシーに関するご質問等は 次項の窓口までお問い合わせください。

13. ポリシーの変更

本プライバシーポリシーは、必要に応じて改定される場合があります。改定があった場合は、 本ページの最終更新日を更新します。

14. お問い合わせ

本プライバシーポリシーに関するご質問は、Chrome ウェブストアの拡張機能ページよりお問い合わせください。
